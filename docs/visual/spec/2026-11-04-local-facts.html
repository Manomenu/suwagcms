Spec

Local facts

Status: approved Date: 2026-11-04 Feature: 14 of the suwagcms feature map Needs before it: procedure-model
Feature map Architecture Spec

TL;DR

A procedure can declare its own localFacts: typed like global facts, written without dots, and gone when the procedure ends. Its steps use them by their short name, and no other procedure can see them.

They are part of the procedure, so they are saved with it and deleted with it. Removing one that a step still uses is refused, and a local fact can never share a name with a global fact of the bot.

12criteria

Problem

After procedure-model, everything a procedure remembers is a global fact. The date of one order would then sit in the bot's catalog for a whole conversation, visible to every procedure and offered to every author, although only one procedure ever means anything by it. A second procedure that happens to use the same name would read a leftover value. Suwchatbot already solves this with localFacts in the procedure, and its reader is the model for these rules.

Goals and non-goals

Goals

  • A procedure keeps its own working values out of the bot's catalog.
  • The same types, constraints and writableBy as a global fact, with the same mistakes.
  • A name always means one thing inside a procedure.
  • A local fact in use cannot be taken away from under a step.

Non-goals optional

  • Editing local facts on the Facts screen: they are edited in the panel of the procedure's creator, a criterion of procedure-creator.
  • Commands for one local fact: a procedure is saved as one whole file, as procedure-model decided.
  • Filling one from an action: action-block.
  • Refusing an edit that narrows a local fact a step relies on: edit-guard.
  • Forgetting the value when a procedure ends: bots run procedures, and the first bot's specs are in its own repository.

Scenarios

1. An agent gives a procedure its own fact

$ suwagcms procedures edit orderValuation --file orderValuation.yaml # declares local fact visitDate, and step ask collects it Saved orderValuation, revision 4. $ suwagcms facts list customer.city text, up to 80 set order.kind enum: house, flat correct

visitDate is not in the bot's list of facts. suwagcms procedures show orderValuation prints it in the procedure.

2. A name the bot already uses

Refused, 1 mistake: fact.local.nameClash Local fact 'city' of procedure 'orderValuation' has the name of a global fact. Inside the procedure the name would be ambiguous. Rename one of them.

3. Another procedure reaches for it

Refused, 1 mistake: reference.missing 'collect' of step 'ask' in 'complaint' names fact 'visitDate', which this procedure does not see. Facts it sees: customer.city, order.kind. Local facts of other procedures are not visible.

4. A local fact still in use

Refused, 1 mistake: reference.missing 'orderValuation' no longer declares local fact 'visitDate', which is used by: step ask (collect), step confirm (when). Change these steps first, or keep the fact.

Behaviour

A local fact

FieldRule
localFactsoptional on a procedure; a map from name to fact; may be empty
namecamelCase with no dot; unique within the procedure; two procedures may each have the same name with different types
type, constraints, description, writableByexactly as for a global fact, including the default set and every mistake in the global-facts spec

Facts have no availability, and a local fact has no revision of its own: the procedure holds both. A save behaves as the “How every save behaves” section of the global-facts spec describes.

What a step sees

A step of a procedure sees the bot's global facts and that procedure's local facts, the latter by short name. Everything procedure-model checks for a fact holds for a local one: a collect cannot name one with writableBy: assign, a condition must fit its type, and a value in oneOf, range or assign must be one it can take.

SituationResult
a step names a local fact of another procedure, by short name or as otherProcedure.namerefused with reference.missing; the message lists what this procedure sees and says local facts of others are not visible
a step names its own local fact as thisProcedure.namerefused the same way: inside the procedure the short name is the only name
a save removes a local fact and a step still uses itrefused with reference.missing, listing every step and the place in it
a save removes a local fact and every use of itaccepted: the result is sound
a local fact has a global fact's namerefused, whichever was saved second; see below
a procedure is deletedits local facts go with it, and their names are free for a global fact
a local fact no step usesallowed at both stages
a collect naming only local factsthe procedure still needs whenStalled before a version

Names shared with global facts

A local fact with a global fact's name would make the name ambiguous inside the procedure, so the rule is on the result of a save and works in both directions. A procedure declaring such a local fact is refused, and so is adding a global fact with such a name, which lists the procedures holding it. edit-guard covers the other clash: a global fact named <procedureId>.<anything>.

The rules are in the validator at the Save stage, so they also hold offline.

Format

This is part of the public contract with bots. It adds an optional field, so it does not raise formatVersion.

Decisions optional

  • Both directions of the “same name as a global fact” clash live here, as the global-facts spec already says; edit-guard keeps the prefix clash, which needs no local fact to exist. One rule on the result covers both directions, so splitting it across two specs would only duplicate its check.
  • No commands for a single local fact: an agent edits the procedure's file, which is how it already reasons about a procedure.
  • The global name procedureId.name is how a bot may report a local fact outside the procedure. In the format a step never writes it, so authors have one name to learn.
  • A local fact no step uses is allowed at both stages: it is harmless at run time, and the same as a global fact nobody uses.
  • A name clash is one mistake on the global fact, naming every procedure that holds the name, whichever side was saved second.

Acceptance criteria

  • AC-local-facts-1 A procedure declaring an enum, an int and a text local fact, saved with suwagcms procedures add --file, reads back with each fact's type, constraints, description and writableBy as written, in YAML and in JSON, and the output of suwagcms procedures show is accepted back by suwagcms procedures edit --file without a change of meaning.
  • AC-local-facts-2 A local fact without writableBy has set; a procedure with no localFacts or an empty one is accepted.
  • AC-local-facts-3 A local fact with a blank description, an unknown type, or constraints a global fact of that type could not have is refused with the same code as for a global fact, and a path inside localFacts of that procedure.
  • AC-local-facts-4 A local fact name with a dot, and one that is not camelCase, are each refused with a mistake and a fix.
  • AC-local-facts-5 A procedure declaring a local fact with the name of a global fact is refused with fact.local.nameClash, naming both; adding a global fact with the name of a local fact is refused with the same code, listing every procedure that holds it.
  • AC-local-facts-6 collect, assign and when can name a local fact of their procedure by its short name, and the rules for facts hold for it: a collect of one with writableBy: assign, a condition that does not fit its type, and a value it can never take are each refused; a procedure whose only collect names local facts still needs whenStalled at the Version stage.
  • AC-local-facts-7 A step naming a local fact of another procedure, by short name or as otherProcedure.name, or its own as thisProcedure.name, is refused with reference.missing, listing the facts this procedure sees.
  • AC-local-facts-8 Two procedures can each hold a local fact of one name with different types, and each is checked against its own.
  • AC-local-facts-9 A save removing a local fact a step still uses is refused with reference.missing, listing every step using it; a save removing the fact and all its uses is accepted.
  • AC-local-facts-10 After a procedure with local facts is deleted, a global fact with one of their names can be added.
  • AC-local-facts-11 Local facts are not listed by suwagcms facts list or on the Facts screen, and suwagcms facts show of one's name is refused as a fact the bot does not have.
  • AC-local-facts-13 The plugin's main skill gives the form of localFacts.

Risks and assumptions

A bot on an SDK older than this field ignores localFacts as an unknown field, and its validator then reports each step using one as reference.missing. That stops the load instead of misleading a customer, so the field does not raise formatVersion.
